# 嵌入和图片生成只在 OpenAI 格式之间透传

客户端要用 `/v1/embeddings` 和 `/v1/images/generations`。这两类请求和对话很不一样：没有多轮、没有工具、没有 Conversation；图片生成按张收费，一次可能要一两分钟；各家的响应形状也不统一（OpenAI 是 `data[]`，硅基流动是 `images[]`，火山方舟的流式事件名和 OpenAI 不同）。问题是网关要不要理解它们，以及怎么选路、怎么判断成功、怎么算钱。

参考的几家：ccLoad 只在 OpenAI 渠道之间透传，图片不计费；new-api 按次固定价、按返回张数重算、嵌入没用量就估算；AxonHub 给模型分类型，不支持图片流式，没用量就当免费。Ntm 的取舍是：只透传，复用对话的选路和容错，钱按返回的东西算。

- **只开两个端点、只接 OpenAI Chat 格式的渠道**（Q220/Q221）。Anthropic 和 Responses 没有对等的接口，不做 IR，也不做格式转换。请求体原样转发，只把 `model` 换成上游模型名；渠道的请求体改写规则是为对话写的，不作用在这两类请求上，请求头规则照常生效（Q226）。网关只检查请求体是 JSON 对象、带非空的 `model`（Q227）。
- **下发模型声明自己的 RequestKind**（Q222）。模型名全局唯一，用错端点返回 404 并指出该用哪个端点。Anthropic 形状的 `/v1/models` 只列对话模型（Q223）。
- **端点从渠道的对话路径推出来**（Q224）。渠道没填路径就用默认的 `/v1/embeddings`、`/v1/images/generations`；填了以 `/chat/completions` 结尾的路径就把结尾换掉、保留查询串；别的自定义路径推不出来，这个渠道不是候选，预览里写明原因。没有为每类请求单独加路径字段。
- **复用 ChatRelay 的选路、冷却、限制、日志和中断**（Q225），只是没有 Affinity，也没有 `previous_response_id`。
- **成功的判据**（Q228）：2xx、JSON 对象、顶层没有 `error`，原样返回。结果是空的（嵌入的 `data` 为空、图片的 `data` 和 `images` 都为空）算软错误，换候选。图片流式原样透传，第一帧就提交；没有 `[DONE]` 也算正常结束（Q232）。
- **用量**（Q229）：嵌入取 `prompt_tokens`，没有就取 `total_tokens`；上游没给就按输入字符估算。图片取 `input_tokens`/`output_tokens` 或 `prompt_tokens`/`completion_tokens`，没给就不估：估出来的数字和图片的实际价钱差太远。
- **图片按张计价**（Q230）：单价行多一列「每张图片」，只能人工填。填了就按返回的图片张数 × 这个价 × 渠道倍率计费，不看 Token；没填就按 Token 单价算；两样都没有就是「无单价」。张数优先取 `usage.generated_images`，否则数返回的条目或流里的完成事件。尺寸和质量不分档。
- **超时和失败切换**（Q233–Q235）：图片的首个事件超时放宽到 5 分钟。图片请求超时不换候选，因为上游可能已经在出图、已经计费；其他失败照常切换。嵌入和图片的 404/405 没有「模型不存在」之类的字样时，只冷却渠道加模型 30 分钟，不冷却整个渠道，免得一个不支持嵌入的中转把对话也拖下线。

## Consequences

- 图片模型不填「每张图片」的单价，又碰上不给用量的上游，就是无单价，不计入费用上限（Q231）。文档站的「计费」页写明了这一点。
- OpenRouter 的图片接口在 `/api/v1/images` 这种推不出来的路径上，现在接不了。
- 编辑图片、变体、语音、重排都没开；`RequestKind` 里的音频和重排仍然没有能用的端点。
- 统计不按 RequestKind 拆分，只有请求日志能按类型筛。
