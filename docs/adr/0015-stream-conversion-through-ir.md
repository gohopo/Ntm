# 流式转换也经过 IR：每种格式一个读取器和一个写出器

只有 OpenAI Chat 和 Anthropic 两种格式时，流式转换是两个直译器：Chat 流译成 Anthropic 流、Anthropic 流译成 Chat 流。加上 OpenAI Responses 之后，两两直译要六个，以后每多一种格式再加 2N 个；每个直译器还都要自己记一遍「第几个工具调用对应对方的第几个块」，同一类错误要在六处分别修。

所以流也有一层 IR：一串按顺序到达的事件——消息开始（带模型和已知的输入用量）、内容块开始（文本、Reasoning、工具调用，工具调用带 id 和名字）、块内增量、块结束、消息结束（带结束原因和用量）、错误。每种格式只写一个读取器把自己的流读成这串事件，一个写出器把这串事件写成自己的流。三种格式是三读三写，第四种格式只多一读一写。事件按 Anthropic 的流形状来定，因为它本来就是按块开始、增量、块结束组织的，另外两种格式都能无损地落到这个形状上。

判断「这一帧是不是 ContentEvent」和读取用量仍然由各格式的流检查器负责，不并进读取器：透传不经过 IR，也要知道 Commit 时刻和用量。

## Consequences

- 原有的两个直译器改写成读取器和写出器，行为以它们的测试为准。
- 每条事件是一个小对象，比直译多一点分配。这是对话流，事件数在每秒几十到几百，接受这个代价。
- 某种格式独有、IR 里没有位置的东西（Responses 的引用标注、Anthropic 的 citations 增量）在转换时丢掉；要保留就得先给 IR 加事件种类，不能在某一对读写器之间私下传。
