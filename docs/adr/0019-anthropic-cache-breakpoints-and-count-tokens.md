# 转 Anthropic 时自动加缓存断点，count_tokens 能问上游就问、问不到就估

OpenAI Chat 和 Responses 的客户端走到 Anthropic 渠道时，请求里没有 `cache_control`。Anthropic 没有断点就不缓存，同一段长对话每一轮都按全价算输入，比走 OpenAI 渠道贵得多。Claude Code 之类的 Anthropic 客户端还会调 `/v1/messages/count_tokens`，以前返回 404。

参考的几家：new-api 不加断点，「缓存永不命中」的问题一直开着；AxonHub 加了断点，碰到过超过 4 个返回 400、第三方中转因为注入的断点返回 403，后来改成客户端写了就不加；LiteLLM 出过数断点漏了 tools、把断点放到思考块和空文本块上的 bug；ccLoad 在客户端没写时最多加 3 个，总数修到 4 个以内，count_tokens 只转给官方地址，其他就本地估算。

- **只在转换时加**（Q241）。OpenAI Chat 或 Responses 入站、写成 Anthropic 请求时才加；Anthropic 入站透传按 ADR-0002 字节照搬，断点由客户端决定。Anthropic 入站转到 OpenAI 或 Responses 上游时断点照旧丢掉：OpenAI 自动缓存，Responses 上游已经用 `prompt_cache_key`（Q243）。
- **客户端写了就照它的**（Q242）。认 OpenAI Chat 里 OpenRouter 的写法：content part、消息、tool 上的 `cache_control`。只要有一个，网关就不再自动加。Responses 入站没有通行写法，不读。
- **自动加的位置**（Q244）：最后一个 tool、最后一个 system 块、最后一条消息里最后一个能放断点的块、倒数第二条 user 消息里最后一个能放断点的块。前三个让下一轮读到这一轮的全部前缀；第四个是给一轮里新增超过 20 个块的情况兜底，因为 Anthropic 只往前找 20 个块。思考块、被屏蔽的思考块和空文本块不能放，往前找。都是 5 分钟（Q246）。
- **整理**（Q245）：客户端写的和自动加的都过一遍。落在写不出或不能放的块上的去掉；超过 4 个时保留最后一个 tool、最后一个 system 和最后两个消息断点；1 小时的排在 5 分钟后面就降成 5 分钟。
- **不用顶层的自动缓存**（Q248）。旧版 Bedrock 会返回 400，第三方端点支不支持不清楚，显式断点哪里都能用。
- **渠道开关**（Q247）。Anthropic 格式的渠道上有「自动加缓存断点」，默认开，已有的渠道也开。关掉后只是不自动加，客户端写的照转。断点在写请求体时就放好，之后才套请求改写规则，规则加了字段不再重数（Q249）。
- **count_tokens**（Q251–Q255）。鉴权和 `/v1/messages` 一样，查 API 密钥、模型白名单和渠道白名单，不查频率、并发、费用上限和可用时段：这个接口不花钱，也不占上游的生成资源。按正常的选路顺序挑第一个 Anthropic 格式、不在冷却的候选，只试一次，请求体只带计数需要的字段。上游不是 2xx 就本地估算，绝不把上游的 404 交给客户端；404/405 记住 24 小时（只在内存里）。本地估算往高处偏 10%：估少了客户端以为上下文还够，结果会超窗口。不写请求日志，Claude Code 调得太频繁。

## Consequences

- 同一段对话每次写出的前缀字节相同，配合会话亲和，长对话从第二轮起大部分输入按缓存读计价。第一次写缓存要多付 25%，只说一句的请求最后一条消息上的断点白写。
- 不到最小前缀长度（按模型 1024 到 4096 Token）的请求，断点被上游静默忽略，没有副作用。
- 请求改写规则会写进去的断点要让出位置：设置或补充顶层 `cache_control` 算 1 个（Q307），设置或补充的值里每出现一个 `cache_control` 也算 1 个（Q316，比如用规则整段写 `system`），去掉的规则不算。网关自己加的和客户端写的合起来最多「4 减去规则里的个数」，最少 0；要去掉时先去靠前的消息断点，再去 tool、system 的，最后一个消息断点最后才去。
- count_tokens 不留记录，网关这边看不到它被调了多少次；需要时看日志。
- 推理强度（`reasoning_effort` 和 `thinking`）当时不互转（Q256）；后来由 ADR-0021 补上。
