# 只支持单实例部署，运行时状态留在进程内存

Ntm 用 SQLite 存储，而 SQLite 无法承担多副本之间的共享可变状态；要横向扩展就得引入 Redis 或换 Postgres。自托管场景下单实例足够，我们明确不支持多副本。

因此 Cooldown 状态、RPM 计数、并发计数全部放进程内存，数据库只存配置与历史记录。重启会丢失 Cooldown 状态，这是可接受的：Cooldown 本就是短时状态，重启后按真实请求重新判定即可。

## Consequences

- 不要为了「顺便支持多副本」往 SQLite 里引入分布式锁、租约或 leader 选举。
- 真要横向扩展，这是一次架构级改造，不是加一张表。
